# HWInfo — 设计文档

> 版本：v1.1  
> 日期：2026-10-19  
> 对应需求文档：v1.2  
> 说明：本版按**现有代码实现**全面校订，修正了早期设计中与实现不符的描述
> （WMI 连接模型、并行与超时机制、驱动版本来源、pci.ids 兜底、UEFI/TPM 检测、
> 显示器连接方式、brief 字段定义等）。已知的实现缺陷与改进方向集中列于
> `docs/后端优化计划.md`。

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| 采集与展示分离 | Collector 只管拿数据，Formatter 只管渲染，互不依赖 |
| 模块独立性 | 每个 Collector 可独立开发、测试、运行，不依赖其他 Collector |
| 容错优先 | 任何单点失败不导致整体崩溃，优雅降级 |
| 可读性优先 | 中文键名 dict，打印即可调试 |
| 渐进增强 | 先保证核心数据正确，再优化格式/性能/扩展 |

### 2.2 数据流

```
用户输入: python main.py cpu gpu --json

    │
    ▼
[main.py] 检测到有参数 → 调用 cli.app.run_cli(argv)
    │
    ▼
[cli/app.py]
    ├── 解析参数: categories=["cpu","gpu"], format="json"
    ├── 加载配置: config/settings.py → 合并 default.yaml + 用户 config.yaml
    ├── resolve_categories(): 解析类别 → 过滤无效项 / 被隐藏项
    │     └── 结果为空列表 → 直接报错退出（exit 2），不静默回退成全量采集
    ├── collectors.load_all(): 导入 9 个模块，触发 @register_collector 副作用
    ├── get_all_collectors() → manager.register(c) 逐个注册实例
    └── 调用: manager.collect(categories=["cpu","gpu"], parallel=...)
    │
    ▼
[core/manager.py] CollectorManager.collect()
    ├── 按 categories / exclude 过滤 + 按 order 排序
    ├── 提交到「模块级共享」ThreadPoolExecutor 并行执行:
    │     ├── cpu_collector.collect() → dict
    │     │     └── 工作线程 finally 中调 cleanup_com() 释放 COM 引用
    │     └── gpu_collector.collect() → dict
    ├── as_completed(timeout = TIMEOUT + 5) 收集已完成任务
    ├── 捕获异常 → 记入 errors；整体超时后未完成的模块标记为"采集超时"
    ├── 从各模块 dict 中提取 "_警告" 键 → 汇总到 result.warnings
    └── 返回: CollectResult(data, errors, warnings, elapsed_seconds, timings)
    │
    ▼
[cli/app.py]
    ├── 根据 format="json" 选择 JsonFormatter
    └── 调用: formatter.render(result) → 输出到 stdout
    │
    ▼
终端显示 JSON 字符串
```

## 3. 核心接口定义

### 3.1 BaseCollector（采集基类）

```python
# core/base.py
from abc import ABC, abstractmethod

class BaseCollector(ABC):
    """所有硬件采集模块的基类"""

    # === 类属性（子类必须定义）===
    name: str = ""          # 模块标识符，如 "cpu"、"gpu"（用于命令行和配置）
    label: str = ""         # 中文显示名，如 "处理器"、"显卡"（用于输出标题）
    order: int = 0          # 显示排序权重（越小越靠前）

    @abstractmethod
    def collect(self) -> dict:
        """
        执行硬件信息采集。

        Returns:
            dict: 中文键名的采集结果字典。
                  成功时返回完整数据。
                  如果部分字段获取失败，该字段值设为 None 并在
                  结果中添加 "_警告" 键说明原因。

        Raises:
            CollectorError: 当整个模块完全无法采集时抛出。
        """
        ...

    def get_brief_fields(self) -> list[str]:
        """
        返回 brief 模式下应显示的键名列表。
        子类可覆写，默认返回全部键。
        """
        return []

    def __repr__(self) -> str:
        return f"<{self.__class__.__name__} name={self.name}>"
```

### 3.2 CollectorManager（调度管理器）

```python
# core/manager.py
from dataclasses import dataclass, field
from concurrent.futures import ThreadPoolExecutor, as_completed

@dataclass
class CollectResult:
    """采集结果汇总"""
    data: dict = field(default_factory=dict)       # {"cpu": {...}, "gpu": {...}}
    errors: list[dict] = field(default_factory=list)  # [{"模块": "cpu", "错误": "..."}]
    warnings: list[str] = field(default_factory=list) # ["无法获取内存条详细信息"]
    elapsed_seconds: float = 0.0                   # 总耗时
    timings: dict = field(default_factory=dict)      # {"cpu": 0.35, "gpu": 1.2} 每模块耗时

class CollectorManager:
    """采集调度中心"""

    TIMEOUT = 10  # 单模块超时秒数（作为整体兜底的基数）

    def __init__(self):
        self._collectors: dict[str, BaseCollector] = {}

    def register(self, collector: BaseCollector) -> None:
        """注册一个 Collector 实例"""
        self._collectors[collector.name] = collector

    def collect(
        self,
        categories: list[str] | None = None,
        exclude: list[str] | None = None,
        parallel: bool = True,
    ) -> CollectResult:
        """
        执行采集。

        Args:
            categories: 要采集的类别列表。None 表示全部。
            exclude: 要排除的类别列表。
            parallel: 是否并行采集（只有一个目标时强制走顺序分支）。

        Returns:
            CollectResult 包含数据、错误、警告、耗时。
        """
        ...

    def list_collectors(self) -> list[dict]:
        """返回所有已注册 Collector 的 name / label / order"""
        ...
```

> **超时语义（与需求文档 §1.6 的对应关系）**
>
> WMI COM 调用一旦进入就无法安全取消（强行 `CoUninitialize` 会导致解释器崩溃），
> 因此实现上采用「**软超时**」而非强制终止：

| 层级 | 机制 | 行为 |
|------|------|------|
| 单模块 | 无独立计时器 | 只能等整体兜底触发时被标记为「采集超时」 |
| 整体 | `as_completed(..., timeout=TIMEOUT+5)` | 放弃等待未完成任务，记入 `errors`，`timings` 中记为 `TIMEOUT` |

> 被放弃的 future 其工作线程仍在后台运行（`ThreadPoolExecutor` 无法取消已启动的任务），
> `cleanup_com()` 也不会执行。改进方向见 `docs/后端优化计划.md` 阶段一。

### 3.2.1 共享线程池

```python
# core/manager.py
_executor: ThreadPoolExecutor | None = None

def _get_shared_executor(max_workers: int) -> ThreadPoolExecutor:
    """获取全局共享线程池（首次创建后复用）"""
    global _executor
    if _executor is None:
        _executor = ThreadPoolExecutor(
            max_workers=max_workers, thread_name_prefix="hwinfo-collect"
        )
    return _executor
```

- **进程内复用**：GUI 的 F5 刷新、设置页保存后的重采都不新建线程池
- **注意事项**：Python 3.9+ 的 `ThreadPoolExecutor` 工作线程非 daemon，解释器正常退出时会 join
  全部线程。极端情况下若某个 WMI COM 调用无限阻塞，可能延迟进程退出（GUI 强制结束进程不受影响）
- **已知限制**：`max_workers` 仅在首次创建时生效，首次采集的类别数量会固化并发度
  （改进方案见 `docs/后端优化计划.md` §1.1）

### 3.3 Registry（注册机制）

```python
# core/registry.py

_REGISTRY: dict[str, type] = {}

def register_collector(cls):
    """
    装饰器：将 Collector 类注册到全局注册表。
    用法：
        @register_collector
        class CPUCollector(BaseCollector):
            name = "cpu"
            ...
    """
    if not cls.name:
        raise ValueError(f"{cls.__name__} 必须定义 name 属性")
    _REGISTRY[cls.name] = cls
    return cls

def get_all_collectors() -> list[BaseCollector]:
    """实例化并返回所有已注册的 Collector（按 order 排序）"""
    instances = [cls() for cls in _REGISTRY.values()]
    return sorted(instances, key=lambda c: c.order)

def get_collector(name: str) -> BaseCollector | None:
    """按名称获取单个 Collector 实例"""
    cls = _REGISTRY.get(name)
    return cls() if cls else None

def get_registered_names() -> list[str]:
    """返回所有已注册的 Collector 名称列表"""
    return list(_REGISTRY.keys())
```

> **注册时机**：`collectors/__init__.py::load_all()` 通过 `import` 副作用触发 9 个模块中的
> `@register_collector` 装饰器。CLI 与 GUI 都在采集前显式调用一次 `load_all()`。

## 4. 各采集模块详细设计

### 4.1 通用约定

- 每个模块文件位于 `collectors/` 目录
- 使用 `@register_collector` 装饰器自动注册
- WMI 查询通过 `utils.wmi_helper.get_wmi()` 获取**当前线程的**连接
- 返回 dict 中，获取失败的字段值设为 `None`
- 模块级致命错误抛出 `CollectorError`
- 非致命问题记录到返回 dict 的 `"_警告"` 键

### 4.2 操作系统 (os_info.py)

| 项目 | 值 |
|------|-----|
| name | `"os"` |
| label | `"操作系统"` |
| order | 10 |
| 数据源 | WMI: `Win32_OperatingSystem` |

**字段映射：**

| 输出键名 | WMI 属性 | 处理 |
|----------|----------|------|
| 系统名称 | Caption | 直接取值 |
| 版本号 | Version + BuildNumber | 拼接为 "10.0.22631" |
| 系统架构 | OSArchitecture | 直接取值 |
| 安装日期 | InstallDate | WMI 时间格式 → "YYYY-MM-DD" |
| 上次启动 | LastBootUpTime | WMI 时间格式 → "YYYY-MM-DD HH:MM:SS" |
| 系统目录 | WindowsDirectory | 直接取值 |
| 用户名 | 通过 `os.environ["USERNAME"]` | — |

**brief 字段：** `["系统名称", "版本号", "系统架构"]`

### 4.3 主板 (motherboard.py)

| 项目 | 值 |
|------|-----|
| name | `"motherboard"` |
| label | `"主板"` |
| order | 20 |
| 数据源 | WMI: `Win32_BaseBoard` + `Win32_BIOS` + `Win32_ComputerSystem` |

**字段映射：**

| 输出键名 | 数据源 | 处理 |
|----------|--------|------|
| 厂商 | Win32_BaseBoard.Manufacturer | strip() |
| 型号 | Win32_BaseBoard.Product | strip() |
| 版本 | Win32_BaseBoard.Version | strip() |
| 序列号 | Win32_BaseBoard.SerialNumber | strip() |
| 芯片组 | 注册表 `Enum\PCI` 扫描 LPC/eSPI 设备（DeviceDesc 关键词匹配） | 尽力获取，失败回退 IDE 控制器 |
| BIOS_厂商 | Win32_BIOS.Manufacturer | strip() |
| BIOS_版本 | Win32_BIOS.SMBIOSBIOSVersion | strip() |
| BIOS_日期 | Win32_BIOS.ReleaseDate | WMI 时间 → "YYYY-MM-DD" |
| UEFI | 注册表 `Control\PEFirmwareType`，回退 GPT 的 ESP 分区检测 | bool / None |
| TPM | 注册表 `Enum\ACPI` 硬件 ID（MSFT0101 / INTC0B00 …） | "已检测到 (v2.0)" / "已检测到" / "未检测到" |

**brief 字段：** `["厂商", "型号", "BIOS_版本"]`

**关键实现说明：**

- **芯片组**：不走 WMI 关联查询（慢），改为扫描注册表 `SYSTEM\CurrentControlSet\Enum\PCI`
  下的 Intel（`VEN_8086`）/ AMD（`VEN_1022`）设备，再按 `DeviceDesc` 是否含
  `lpc` / `espi` / `isa bridge` / `fch` 判定是否为芯片组南桥；耗时 < 50ms。
  无命中时回退到 `Win32_IDEController` 的名称。
- **UEFI（分层降级）**：
  1. 注册表 `HKLM\SYSTEM\CurrentControlSet\Control\PEFirmwareType`（微软官方方式）
     —— `1` = BIOS，`2` = UEFI，`3` = 混合
  2. 查询 `root\Microsoft\Windows\Storage` 命名空间的 `MSFT_Partition`，
     判断是否存在 GPT 的 EFI 系统分区（ESP，GUID `C12A7328-F81F-11D2-BA4B-00A0C93EC93B`）
     —— BIOS 只能从 MBR 磁盘引导，不会存在 ESP
- **TPM**：优先查 `Enum\ACPI` 下的 TPM 硬件 ID（`MSFT0101` = TPM 2.0、`MSFT0102` = 1.2、
  `INTC0B00`/`INTC0C00` = Intel PTT、`ATMEL`/`NTC`/`STM`/`IFX` = 厂商 TPM）；
  回退 `Services\TPM` 服务键与 `SOFTWARE\Microsoft\Tpm` 键。
  不使用 `Get-Tpm`（PowerShell 启动开销大）。

### 4.4 处理器 (cpu.py)

| 项目 | 值 |
|------|-----|
| name | `"cpu"` |
| label | `"处理器"` |
| order | 30 |
| 数据源 | WMI: `Win32_Processor` + psutil + 注册表 |

**字段映射：**

| 输出键名 | 数据源 | 处理 |
|----------|--------|------|
| 名称 | Win32_Processor.Name | strip() 去多余空格 |
| 厂商 | Win32_Processor.Manufacturer | 直接取值 |
| 架构 | Win32_Processor.Architecture | 数字→文本映射 (9="x64", 12="ARM64") |
| 插槽 | Win32_Processor.SocketDesignation | 直接取值 |
| 核心数 | Win32_Processor.NumberOfCores | int |
| 线程数 | Win32_Processor.NumberOfLogicalProcessors | int |
| 基础频率_MHz | Win32_Processor.MaxClockSpeed | int（注：WMI 此字段实为最大频率） |
| L2缓存_MB | Win32_Processor.L2CacheSize | int, 单位 KB→MB 换算 |
| L3缓存_MB | Win32_Processor.L3CacheSize | int, 单位 KB→MB 换算 |
| 指令集 | 注册表 `HKLM\HARDWARE\DESCRIPTION\System\CentralProcessor\0` 的 `Identifier` | 列表（启发式推断） |
| 虚拟化 | Win32_ComputerSystem.HypervisorPresent | bool / None |
| 当前负载_百分比 | psutil.cpu_percent | float |

**brief 字段：** `["名称", "核心数", "线程数", "基础频率_MHz"]`

**关键实现说明：**

- **指令集（启发式推断，非精确探测）**：读取注册表 `Identifier`，
  若包含 `intel64` / `authenticamd` 则在固定的 SSE~SSE4.2 基础上追加 `AVX`、`AVX2`。
  该推断对绝大多数现代 x64 CPU 成立，但**不覆盖** AVX-512、FMA、SHA，
  且对 2013 年前的 AMD（如 Bulldozer）会误报 AVX2。
  精确探测方案（CPUID）见 `docs/后端优化计划.md` §2.1。
- **虚拟化**：主路径用 `Win32_ComputerSystem.HypervisorPresent`（避免调用极慢的 `systeminfo`）；
  失败时回退注册表 `Control\DeviceGuard\EnableVirtualizationBasedSecurity`。
  注意 VBS 开启 ≠ VT-x 开启，该回退属近似判断（改进见优化计划 §2.7）。
- **当前负载**：`psutil.cpu_percent(interval=None)` 先预热记录采样起点，
  再取 `psutil.cpu_percent(interval=0.1)` 得到 0.1s 窗口内的负载值。

**返回结构：**
```python

    "总容量_GB": 32,
    "已使用_GB": 14.2,
    "使用率_百分比": 44.0,
    "插槽总数": 4,
    "已用插槽": 2,
    "通道模式": "双通道",

```

**brief 字段：** `["总容量_GB", "已用插槽"]`（顶层），每条：`["插槽", "厂商", "容量_GB", "类型", "频率_MHz", "CL", "电压_V"]`

**关键实现说明：**

- **CL 解析**：优先匹配型号字符串中的显式写法（正则 `CL\s*(\d+)`，大小写不敏感），
  如 `"CL36-44-44 D5-7200"` → 36、`"cl28-34-34"` → 28；
  不含显式 CL 的厂商型号（如 `"F5-7200J3646G24GX2-TZ5RK"`）返回 `None`，不做猜测。
- **通道模式推断**（启发式）：按已插条数判断 —— 0 条→未知，1 条→单通道，2 条→双通道，
  4 条且插槽总数 ≥ 8→四通道，否则→双通道，其他→"N 条"。
  未按实际通道拓扑推断（四通道板插 2 条实为单通道），改进见优化计划 §2.5。
- **总容量兜底**：psutil 不可用时，用各内存条 `Capacity` 求和。

- **显存溢出处理**：`Win32_VideoController.AdapterRAM` 是 32 位整数，超过 4GB 会溢出成错误值。

- **pci.ids 兜底触发条件**：`PNPDeviceID` 含 `PCI\` 且（名称为空 / 为「未知显卡」/ 含

  完全不触发 1.6MB 文件的解析开销。
- **pynvml 匹配**：当前按「厂商字段含 nvidia」筛选显卡后，与 `nvmlDeviceGetHandleByIndex(i)`

### 4.7 存储设备 (storage.py)

| 项目 | 值 |
|------|-----|
| name | `"storage"` |
| label | `"存储设备"` |
| order | 60 |
| 数据源 | WMI: `Win32_DiskDrive` + `Win32_LogicalDisk` + `Win32_DiskDriveToDiskPartition` |

**采集逻辑：**
1. `Win32_DiskDrive` 获取物理磁盘列表
2. 通过 `disk.associators(wmi_result_class="Win32_DiskPartition")` 取该盘的分区，
   再对每个分区 `part.associators(wmi_result_class="Win32_LogicalDisk")` 取逻辑盘，

>
> 这两个字段只能通过 PowerShell `Get-PhysicalDisk` 获取（WMI 无等价接口）。
> PowerShell 进程启动固有开销约 1.5–2s，是整个工具最大的性能瓶颈。
> 且 HealthStatus 需要管理员权限，普通用户下始终返回“需管理员权限”，实用价值低。
> 因此 v0.1 不采集这两个字段，磁盘类型通过关键词 + PNP ID 推断。
> 后续版本可考虑通过配置开关按需启用。

### 4.8 网络设备 (network.py)

| 项目 | 值 |
|------|-----|
| name | `"network"` |
| label | `"网络设备"` |
| order | 70 |
| 数据源 | WMI: `Win32_NetworkAdapter` + `Win32_NetworkAdapterConfiguration` + netsh |

**采集逻辑：**
1. `Win32_NetworkAdapter(PhysicalAdapter=True)` 获取物理网卡
2. **过滤规则**：`NetConnectionID` 为空 **且** `NetConnectionStatus != 2`（已连接）的条目视为
   无效虚拟适配器并跳过
3. 通过名称关键词 + `AdapterType` 区分有线/无线
4. `Win32_NetworkAdapterConfiguration(IPEnabled=True)` 按 `Index` 关联取 IPv4 / 子网 / 网关
5. 无线额外信息：`netsh wlan show interfaces` 获取 SSID 和信号
6. 驱动版本：注册表按需读取（`utils/registry.py`）

**字段映射（每个网卡）：**

| 输出键名 | 数据源 | 处理 |
|----------|--------|------|
| 类型 | 名称关键词 + AdapterType | "以太网" / "无线" |
| 名称 | Win32_NetworkAdapter.Name | 直接取值 |
| 厂商 | Win32_NetworkAdapter.Manufacturer | 直接取值 |
| MAC | Win32_NetworkAdapter.MACAddress | 直接取值 |
| 速率_Gbps | Win32_NetworkAdapter.Speed | bps → Gbps |
| 状态 | Win32_NetworkAdapter.NetConnectionStatus | MSDN 完整状态码映射 0~12 |
| IPv4 | Win32_NetworkAdapterConfiguration.IPAddress[0] | 取第一个 IPv4（跳过 IPv6） |
| 子网掩码 | Win32_NetworkAdapterConfiguration.IPSubnet[0] | 直接取值 |
| 网关 | Win32_NetworkAdapterConfiguration.DefaultIPGateway[0] | 直接取值 |
| 驱动版本 | 注册表 `Enum\<PNPDeviceID>` → `Control\Class\<path>\DriverVersion` | 直接取值 |
| SSID | netsh wlan show interfaces（仅无线且已连接） | 解析输出 |
| 信号_dBm | netsh wlan show interfaces（仅无线且已连接） | 解析百分比→dBm |

**brief 字段（每个网卡）：** `["名称", "驱动版本"]`

**关键实现说明：**

- **状态码映射**（MSDN `Win32_NetworkAdapter.NetConnectionStatus`）：
  `0` 未连接、`1` 正在连接、`2` 已连接、`3` 正在断开、`4` 硬件不存在、`5` 硬件禁用、
  `6` 硬件故障、`7` 媒体断开、`8` 认证中、`9` 认证成功、`10` 认证失败、
  `11` 无效地址、`12` 凭证不足；未知值显示为「状态码: N」。
- **速率过滤**：过滤 `int64` 最大值（`9223372036854775807`）等无效值；
  上限判定为 `0 < speed <= 10_000_000_000`，即真实 10G 网卡的等号保留，
  超过 10Gbps 的通常是虚拟适配器的假速率。
- **驱动版本**：刻意**不使用** `Win32_PnPSignedDriver`（枚举全部驱动耗时 3~5s），
  改走注册表路径，耗时 < 10ms。
- **无线判定**当前只依据名称关键词与 `AdapterType`，未使用 `PNPDeviceID`
  （需求文档原稿曾写「AdapterType 或 PNPDeviceID」，以现实现为准）。
- **WiFi 信息**：`netsh` 输出按**本地 ANSI 代码页**解码（中文系统为 cp936），
  强制 UTF-8 会导致「信号强度」等中文字段解析失败。
  信号强度为百分比，按 `dBm ≈ (percent - 100) / 2` 粗略换算。

### 5.1 wmi_helper.py — WMI 连接管理

```python
# utils/wmi_helper.py
import threading

# 使用线程本地存储，每个线程拥有独立的 WMI 连接
_thread_local = threading.local()

# win32com 动态分发（Dispatch/GetObject）存在全局类型缓存，
# 多线程并发首次初始化会触发竞态（"接口未知"/"参数错误"等间歇性 COM 错误），
# 因此连接的首次创建需全局串行化。
_init_lock = threading.Lock()

def get_wmi():
    """获取当前线程的 root\cimv2 WMI 连接（线程本地单例）"""
    if not hasattr(_thread_local, 'wmi_connection') or _thread_local.wmi_connection is None:
        with _init_lock:
            # 双重检查：等待锁期间可能已被本线程创建
            if not hasattr(_thread_local, 'wmi_connection') or _thread_local.wmi_connection is None:
                import pythoncom
                import wmi
                pythoncom.CoInitialize()
                _thread_local.wmi_connection = wmi.WMI()
    return _thread_local.wmi_connection

def get_wmi_root():
    """获取当前线程的 root\wmi WMI 连接（用于显示器 EDID）"""

                import wmi
                pythoncom.CoInitialize()
                _thread_local.wmi_root = wmi.WMI(namespace="root\\wmi")
    return _thread_local.wmi_root
```

**关键设计说明：**

- **线程本地连接（不是全局单例）**：WMI 基于 COM，每个线程必须独立初始化 COM
  并创建自己的连接，**不能跨线程共享全局连接**。
  需求文档早期版本写的「全局复用单一连接」已废弃，改为线程本地单例。
- **首次初始化锁**：`win32com` 动态分发存在全局类型缓存，多线程并发首次初始化会触发
  间歇性 COM 错误（「接口未知」/「参数错误」）。用全局 `Lock` + 双重检查串行化首次创建。
- **`cleanup_com()` 不调用 `CoUninitialize()`**：WMI 库内部会创建大量 COM 对象，
  部分对象可能在 GC 之前就被 `CoUninitialize` 报错。改为显式 `del` 线程局部引用 +
  `gc.collect()`，线程池线程结束时由 OS 自动清理 COM 状态。
  该函数在 `core/manager.py` 的工作线程 `finally` 中调用。

```python
class PciIdsDatabase:
    """pci.ids 文件解析与查询"""

    def __init__(self, filepath: str = None):
        """
        加载 pci.ids 文件。
        默认路径: 程序目录下 data/pci.ids
        """
        self._vendors: dict[str, str] = {}       # {"10de": "NVIDIA Corporation"}
        self._devices: dict[str, str] = {}       # {"10de:2782": "GeForce RTX 4070 Ti"}
        self._load(filepath)

        解析 pci.ids 文件格式：
        - 无缩进行: 'XXXX  Vendor Name'
        - 一级Tab缩进: '\tXXXX  Device Name'
        - 二级Tab缩进: '\t\tXXXX XXXX  Subsystem Name'（忽略）
        - '#' 开头为注释，跳过
        """
        ...

    def get_vendor(self, vendor_id: str) -> str | None:
        """查询厂商名。vendor_id 如 '10de'（小写，无0x前缀）"""
        return self._vendors.get(vendor_id.lower())

    def get_device(self, vendor_id: str, device_id: str) -> str | None:
        """查询设备名。返回如 'GeForce RTX 4070 Ti'"""
        key = f"{vendor_id.lower()}:{device_id.lower()}"

        输出: 'NVIDIA Corporation GeForce RTX 4070 Ti' 或 None
        """
        ...
```

### 5.3 powershell.py — PowerShell / 命令行调用封装

```python
# utils/powershell.py
import subprocess
import json
import locale

def _no_window_flags() -> int:

def run_powershell(command: str, timeout: int = 10) -> str:
    """
    执行 PowerShell 命令，返回 stdout 文本。

    通过先设置 [Console]::OutputEncoding 强制 PowerShell 输出 UTF-8，
    避免中文系统默认 GBK 输出与 utf-8 解码不匹配导致的乱码。
    """
    full_command = (
        "[Console]::OutputEncoding=[System.Text.Encoding]::UTF8; " + command
    )
    result = subprocess.run(
        ["powershell", "-NoProfile", "-NonInteractive", "-Command", full_command],
        capture_output=True, text=True, timeout=timeout,
        encoding="utf-8", errors="replace",
        creationflags=_no_window_flags(),
    )
    if result.returncode != 0:
        raise subprocess.CalledProcessError(
            result.returncode, command, result.stdout, result.stderr
        )
    return result.stdout.strip()

def run_powershell_json(command: str, timeout: int = 10) -> list | dict:
    """
    执行 PowerShell 命令并以 JSON 解析输出。
    命令应包含 '| ConvertTo-Json' 管道。
    """
    output = run_powershell(command, timeout)
    if not output:
        return {}
    return json.loads(output)

def run_command(command: list[str], timeout: int = 10) -> str:
    """
    执行任意命令行程序，返回 stdout 文本。
    用于调用 netsh、wmic 等。

    按本地 ANSI 代码页解码输出（中文系统为 cp936/GBK），
    保证 "信号强度" 等中文字段可被正确解析。
    """
    result = subprocess.run(
        command, capture_output=True, text=True, timeout=timeout,
        encoding=_ansi_encoding(), errors="replace",
        creationflags=_no_window_flags(),
    )
    if result.returncode != 0:
        raise subprocess.CalledProcessError(
            result.returncode, command, result.stdout, result.stderr
        )
    return result.stdout.strip()
```

**关键设计说明：**

- **两种编码策略并存，取决于被调用程序**：
  | 函数 | 目标程序 | 编码策略 |
  |------|---------|---------|
  | `run_powershell` | `powershell` | 命令前置 `[Console]::OutputEncoding=UTF8`，按 utf-8 解码 |
  | `run_command` | `netsh` / `wmic` | 按本地 ANSI 代码页（`locale.getpreferredencoding`）解码 |
  |  |  | 中文系统为 cp936，强制 utf-8 会让「信号强度」等字段解析失败 |
- **`CREATE_NO_WINDOW`**：GUI 程序下调用子进程不再闪现黑色控制台窗口。

```python
    # 1. 加载配置

    manager.TIMEOUT = settings.get_timeout()

    result = manager.collect(categories=categories, parallel=settings.is_parallel())

    # 6. 选择 formatter 并输出
    if args.json:

    else:

    if not args.json:
```

## 9. 关键实现细节

### 9.1 并行采集与超时

```python
# core/manager.py 核心逻辑

def _collect_parallel(self, targets, result) -> None:
    """并行采集"""
    def _run_collector(collector):
        """在工作线程中执行采集，完成后清理 COM"""
        t0 = time.perf_counter()
        try:
            data = collector.collect()
            return data, round(time.perf_counter() - t0, 3)
        finally:
            from utils.wmi_helper import cleanup_com
            cleanup_com()

    executor = _get_shared_executor(len(targets))
    future_map = {
        executor.submit(_run_collector, collector): collector
        for collector in targets
    }

    try:
        # as_completed 的 timeout 是整体兜底：WMI COM 调用可能无限阻塞，
        # 超时后放弃等待，未完成模块由外层 except 标记为超时。
        # 注意：as_completed 只产出已完成的 future，
        # 因此 future.result() 不会超时，无需再传 timeout。
        for future in as_completed(future_map, timeout=self.TIMEOUT + 5):
            collector = future_map[future]
            try:
                data, elapsed = future.result()
                result.data[collector.name] = data
                result.timings[collector.name] = elapsed
            except CollectorError as e:
                result.errors.append({"模块": collector.name, "错误": str(e)})
            except Exception as e:
                result.errors.append({"模块": collector.name, "错误": f"未知错误: {e}"})
    except FuturesTimeoutError:
        logger.error("并行采集整体超时(%ss)，未完成模块标记为超时", self.TIMEOUT + 5)
        for collector in future_map.values():
            if collector.name not in result.data:
                result.errors.append({"模块": collector.name, "错误": "采集超时"})
                result.timings[collector.name] = self.TIMEOUT
```

**与早期设计的差异（以现实现为准）：**

| 项 | 早期设计 | 现实现 |
|----|---------|--------|
| 线程池 | `with ThreadPoolExecutor(...)` 每次新建 | 模块级共享池，进程内复用 |
| 超时粒度 | `future.result(timeout=TIMEOUT)` per-module | `as_completed(timeout=TIMEOUT+5)` 整体兜底 |
| 超时异常 | 捕获 `TimeoutError` 单独处理 | 由 `FuturesTimeoutError` 统一捕获，未完成模块在 except 分支标记 |
| COM 清理 | 无 | 工作线程 `finally` 中 `cleanup_com()` |
| 单模块计时 | 无 | `result.timings` 记录每模块耗时 |

**已知限制与改进方向**（详见 `docs/后端优化计划.md` 阶段一）：

1. `max_workers` 仅在共享池首次创建时固化，类别数量变化会影响并发度
2. 被放弃的 future 其工作线程仍在后台运行，`cleanup_com()` 不会执行；
   若 WMI 调用永久挂起，该线程槽位被永久占用
3. 无真正意义的 per-module 超时（WMI COM 调用无法安全取消）

### 9.2 终端兼容性检测

```python
# utils/format_utils.py

import os
import sys

def supports_unicode() -> bool:
    """检测终端是否支持 Unicode 框线字符"""
    if os.environ.get("HWINFO_FORCE_ASCII"):
        return False
    # Windows Terminal 设置此环境变量
    if os.environ.get("WT_SESSION"):
        return True
    # 尝试检测代码页
    try:
        return sys.stdout.encoding.lower().replace("-", "") == "utf8"
    except:
        return False

def supports_color() -> bool:
    """检测终端是否支持 ANSI 颜色"""
    if os.environ.get("HWINFO_NO_COLOR"):
        return False
    if os.environ.get("WT_SESSION"):
        return True
    # 尝试启用 Windows VT100 模式
    try:
        import ctypes
        kernel32 = ctypes.windll.kernel32
        handle = kernel32.GetStdHandle(-11)  # STD_OUTPUT_HANDLE
        mode = ctypes.c_ulong()
        kernel32.GetConsoleMode(handle, ctypes.byref(mode))
        # ENABLE_VIRTUAL_TERMINAL_PROCESSING = 0x0004
        return bool(mode.value & 0x0004) or kernel32.SetConsoleMode(handle, mode.value | 0x0004)
    except:
        return False

def force_utf8_stdout():
    """强制 stdout 使用 UTF-8 编码，解决 GBK 乱码"""
    import io
    if sys.stdout.encoding.lower().replace("-", "") != "utf8":
        sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8", errors="replace")
```

### 9.5 GUI 后台采集线程

```python
# gui/worker.py

class CollectWorker(QThread):
    """后台硬件信息采集线程"""

    # 注意：不能命名为 finished，否则会遮蔽 QThread 内建的 finished 信号
    collect_finished = Signal(object)            # 携带 CollectResult
    category_done = Signal(str, object, float)   # 类别名 / 数据 / 耗时
    error = Signal(str)                          # 携带错误信息
    progress = Signal(str)                       # 携带当前状态文本

    def run(self) -> None:
        """在工作线程中执行采集"""
        try:
            ...
            manager = CollectorManager()
            for c in get_all_collectors():
                manager.register(c)
            result = manager.collect(
                categories=self._categories,
                parallel=False,                 # GUI 走顺序路径
                on_category=self._on_category,  # 每完成一类即时回填
            )
            self.collect_finished.emit(result)
        except Exception as e:
            logger.exception("后台采集线程异常")
            self.error.emit(str(e))

    def _on_category(self, name: str, data, elapsed: float) -> None:
        """采集回调（工作线程内）→ 转成 Qt 信号发到主线程"""
        self.category_done.emit(name, data, elapsed)
```

**为什么 GUI 必须顺序采集**：`win32com` 的动态分发在进程内共享一份全局类型
缓存，多个采集线程首次访问属性时会互相阻塞（CLI 偶发、GUI 必现，表现为
「全部类别采集超时」）。顺序执行同时还让进度可以**逐类回填**——首屏不必等待
全部类别完成。CLI 仍走并行路径。

**副作用（已确认并接受）**：`core/manager.py::TIMEOUT`（单模块超时兜底）
只在并行路径生效，GUI 顺序路径不适用，因此设置页不提供「单模块超时」控件。
`CollectWorker` 保留 `timeout` 形参但加注释说明其不生效。

`manager.collect()` 的 `on_category(name, data, elapsed)` 在并行/顺序两条路径
都会回调，默认 `None`，不影响 CLI 行为。

**启动预热**（`gui/app.py::_preload_backend`）：在主线程预先导入
`pythoncom` / `wmi` / `pynvml` 并执行 `collectors.load_all()`，把首次导入与
COM 初始化开销挪到窗口显示之前，避免首屏卡顿。

**关窗安全**（`gui/main_window.py::closeEvent`）：采集线程可能被 WMI COM 调用阻塞，
`wait()` 超时后不能直接放行关闭——QThread 对象随窗口销毁会触发
「QThread: Destroyed while thread is still running」崩溃。
处理方式：拒绝本次关闭并挂接线程结束回调，线程退出后自动关窗。

**COM 噪音抑制**（`gui/app.py::_suppress_com_noise`）：pythoncom C 扩展在解释器关闭时
会输出「Win32 exception」消息（COM 对象被 GC 释放所致，不影响功能）。
在 `app.exec()` **之后**执行两次 `gc.collect()` 并将 stderr 重定向到 devnull。
清理代码必须放在 `app.exec()` 之后——放在 `sys.exit()` 内部是不可达的死代码。

**Qt 实现坑（已踩并规避）：**

- 自绘文本必须自己量高度：用 `QFontMetricsF.boundingRect(rect, TextWordWrap, text)` 的行数，
  再乘自定的行距，才能和 `drawText(..., TextWordWrap)` 的实际排版一致。
- `TextWordWrap` **不会**在无空格的长串里断行（序列号 / macOS 风格路径会被裁掉）；
  且 `TextWrapAnywhere` 会粗暴拆词。做法是给 mono 值在 `_ : / \ . -` 后插零宽空格
  （`soft_breaks()`），等价于原型的 `overflow-wrap: break-word` 但优先在分隔符处断。
- Qt 离屏平台（`QT_QPA_PLATFORM=offscreen`）字体库为空，文字全成方框；
  截图必须用 `QT_QPA_PLATFORM=windows` + `window.setAttribute(WA_DontShowOnScreen, True)`。
- `QFont.setPixelSize` 只接受整数，字号为整数 px（原型 CSS 可用 13.8px，约差 3–6%）。
- 截图/测量脚本必须 `set_zoom(1.0)`，否则顶栏与边距按 `gui.zoom` 放大、画板可用高变少。
- 高 DPI 下窗口尺寸按**逻辑像素**给，写死尺寸会让画板在缩放屏上被挤出可视区
  → 默认尺寸按 `availableGeometry()` 计算。

## 10. 错误处理策略

### 10.1 错误分级

| 级别 | 含义 | 处理方式 |
|------|------|----------|
| 致命 (CollectorError) | 整个模块无法工作（如 WMI 服务不可用） | 该模块输出为空，记入 errors |
| 警告 (Warning) | 部分字段获取失败（如无法获取内存条详情） | 字段值设为 None 或提示文本，记入 warnings |
| 信息 (Info) | 非异常但值得提示（如"以管理员运行更完整"） | 仅在末尾提示 |

### 10.2 Collector 内部错误处理模板

```python
# collectors/memory.py 示例

@register_collector
class MemoryCollector(BaseCollector):
    name = "memory"
    label = "内存"
    order = 40

    def collect(self) -> dict:
        try:
            c = get_wmi()
        except Exception as e:
            raise CollectorError(self.name, f"无法访问 WMI: {e}")

        warnings = []

        # 局部失败 → 降级 + 警告
        try:
            sticks = c.Win32_PhysicalMemory()
        except Exception:
            sticks = []
            warnings.append("无法获取内存条详细信息")

        ...

        result = {
            "总容量_GB": total_gb,
            ...
            "内存条": memory_sticks,
        }
        if warnings:
            result["_警告"] = warnings
        return result
```

**约定：**

- 模块级失败（拿不到 WMI 连接、没有任何设备）→ `raise CollectorError(...)`
- 局部失败（某个子项取不到）→ 字段置 `None` 或降级值，必要时追加 `_警告`
- `_警告` 由 `CollectorManager.collect()` 统一提取到 `result.warnings`，
  并从模块数据字典中 `pop` 掉（不污染展示层输出）

> 注：早期模板中的 SMART 采集代码**未实现**——v0.1 刻意不采集磁盘健康信息，
> 详见 §4.7 的设计决策。
