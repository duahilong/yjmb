# HWInfo — Windows 硬件检测工具 需求文档

> 版本：v1.1  
> 日期：2026-07-31  
> 状态：需求确认阶段

---

## 1. 项目概述

### 1.1 项目目标

开发一款 Windows 平台下的硬件检测工具，能够全面采集当前电脑的硬件信息并以清晰、直观的方式展示，类似于「鲁大师」「游戏加加」的硬件检测功能。

### 1.2 开发语言

Python

### 1.3 目标平台

Windows 10 / 11（64-bit）

### 1.4 产品形态

- **第一阶段**：CLI 命令行工具（开发验证 + 辅助使用）
- **第二阶段**：GUI 桌面应用（主产品形态）
- **最终交付**：打包为单文件 EXE，双击即可运行 GUI

### 1.5 运行环境与前置条件

| 项目 | 要求 |
|------|------|
| Python 版本 | ≥ 3.10（使用 `match` 语法、`list[str]` 类型提示等） |
| 操作系统 | Windows 10 (1809+) / Windows 11，64-bit |
| WMI 服务 | 需正常运行（`winmgmt`），精简系统可能被禁用 |
| 终端编码 | 程序启动时强制设置 `stdout` 为 UTF-8，避免 GBK 乱码 |
| 管理员权限 | 非必须，但部分信息（SMART 详情）需要（见 2.8 权限策略） |

### 1.6 性能要求

| 指标 | 目标 |
|------|------|
| 全量采集耗时 | ≤ 5 秒（普通 SSD 主机） |
| 采集方式 | 各模块**并行**执行（`concurrent.futures.ThreadPoolExecutor`） |
| 单模块超时 | 单个 Collector 超过 10 秒未返回则跳过，标记为超时错误 |
| WMI 连接 | 全局复用单一连接，避免重复创建开销 |

## 2. 功能需求

### 2.1 硬件信息采集（核心功能）

采集以下 **9 大类**硬件信息：

| # | 类别 | 采集内容 |
|---|------|----------|
| 1 | 操作系统 | 系统名称、版本号、架构、安装日期、上次启动时间 |
| 2 | 主板 | 厂商、型号、版本、序列号、芯片组、板型、BIOS 厂商/版本/日期、UEFI、TPM |
| 3 | 处理器 (CPU) | 名称、厂商、架构、插槽、核心/线程数、基础频率、最大睿频、缓存(L2/L3)、指令集、虚拟化支持、当前负载 |
| 4 | 内存 (RAM) | 总容量、已使用量、插槽总数/已用数、通道模式、每条内存的插槽位置/厂商/型号/容量/类型/频率/位宽/电压/序列号 |
| 5 | 显卡 (GPU) | 独显/核显分别列出；厂商、显存容量/类型、总线接口、驱动版本/日期、DirectX 版本、当前输出分辨率/刷新率、状态、负载、显存使用 |
| 6 | 存储设备 | 每块磁盘的型号、类型(SSD/HDD，通过关键词推断)、接口(NVMe/SATA)、容量、固件、序列号；分区信息（盘符/文件系统/已用/总容量）。注：健康状态和介质类型因依赖 PowerShell（启动耗时~2s）且需管理员权限，v0.1 不采集 |
| 7 | 网络设备 | 有线/无线分别列出；厂商、型号、MAC 地址、速率、总线位置、连接状态、IPv4/子网/网关、SSID 及信号强度(无线) |
| 8 | 音频设备 | 所有声卡；厂商、型号、总线位置（板载/GPU附带/USB外接）、驱动版本、状态 |
| 9 | 显示器 | 厂商、型号、制造年份/周、分辨率、刷新率、连接方式(DP/HDMI)、当前状态 |

### 2.2 不采集的内容

- USB 外设（热插拔设备，不属于机器固有硬件）
- PCIe 全量设备列表（数据量过大，无实际展示价值）
- 电池信息（非目标场景）

### 2.3 厂商 ID 翻译

- 硬件设备的 VEN/DEV ID 需翻译为可读的品牌名称
- 方案：内置 `pci.ids` 离线数据库（来源：pci-ids.ucw.cz）
- 优先级：
  1. 使用 WMI 返回的设备友好名称（绝大多数设备有）
  2. WMI 无名称时，查询本地 pci.ids 翻译
  3. pci.ids 也查不到时，显示原始 VEN/DEV ID

### 2.4 采集与展示分离

- **采集层**：尽可能全面地采集所有硬件信息，输出为结构化数据
- **展示层**：根据用户配置/参数，决定显示哪些类别、哪些字段
- 采集到的信息不要求全部展示，用户可自定义显示/隐藏

### 2.5 显示控制

- CLI 阶段：通过命令行参数控制（如 `hwinfo cpu gpu`、`--hide audio`）
- 配置文件：持久化用户的显示偏好（YAML 格式）
- GUI 阶段：设置页面提供开关/复选框

### 2.6 输出格式

- 终端美化输出（框线、分组、状态符号）— 默认
- JSON 输出（`--json` 参数）— 调试及数据交换
- HTML 报告 — 后续扩展

### 2.7 容错处理

- 单个采集模块失败不影响其他模块
- 需要管理员权限的信息（如 SMART 详细数据），无权限时给出提示而非报错
- 采集结束时汇总报告错误/警告数量

### 2.8 权限策略

- 程序启动时检测当前是否以管理员身份运行
- **非管理员模式**（默认）：正常采集大部分信息，以下字段可能缺失：
  - 磁盘 SMART 详细数据（健康度百分比、温度、写入量）
  - NVMe 寿命信息
  - 部分底层传感器数据
- 缺失字段在输出中标注为 `「需管理员权限」`
- 程序不强制要求管理员，但在输出末尾提示：`提示：以管理员运行可获取更完整的磁盘健康信息`

### 2.9 多设备场景

| 场景 | 处理方式 |
|------|----------|
| 多块显卡（如双 N 卡） | 按 `[独显 0]` `[独显 1]` `[核显]` 编号分别列出 |
| 多个显示器 | 按 `[显示器 0]` `[显示器 1]` 编号，标注主/副 |
| 多块同型号硬盘 | 按磁盘编号 `[磁盘 0]` `[磁盘 1]` 区分，显示序列号 |
| 多条同型号内存 | 按插槽位置 `[DIMM_A1]` `[DIMM_B1]` 区分 |
| 多个同类网络设备 | 按类型分组 `[以太网 0]` `[无线 0]` 编号 |

### 2.10 终端兼容性

- 程序启动时检测终端是否支持 ANSI 转义序列（颜色/Unicode 框线）
- **支持时**（Windows Terminal / PowerShell 7+）：使用彩色输出 + Unicode 框线
- **不支持时**（老版 cmd.exe）：降级为纯 ASCII 分隔线 + 无颜色
- 检测方式：检查 `os.environ.get("WT_SESSION")` 或尝试启用 VT100 模式
- 提供 `--no-color` 参数强制关闭颜色

### 2.11 日志与调试

- 提供 `--debug` 参数，输出每个 Collector 的执行耗时、WMI 查询语句、异常堆栈
- 调试信息输出到 **stderr**，不干扰正常的 stdout 数据输出
- 不写日志文件（CLI 阶段），保持轻量
- 后续 GUI 阶段可增加文件日志

### 2.12 版本与自身信息

- `hwinfo --version` 输出工具版本号（如 `HWInfo v0.1.0`）
- 终端美化输出的头部包含工具名称和版本号
- 版本号定义在 `pyproject.toml` 中，代码通过 `importlib.metadata` 读取

### 2.13 `--brief` 简洁模式字段定义

每类在 brief 模式下仅显示以下关键字段：

| 类别 | brief 显示字段 |
|------|----------------|
| 操作系统 | 系统名称、版本号、架构 |
| 主板 | 厂商、型号、BIOS 版本 |
| CPU | 名称、核心/线程数、最大睿频 |
| 内存 | 总容量、频率、条数 |
| 显卡 | 名称、显存容量、驱动版本 |
| 存储 | 型号、类型、容量 |
| 网络 | 型号、状态、IPv4 |
| 音频 | 名称、状态 |
| 显示器 | 型号、分辨率、刷新率 |

### 2.14 配置文件

- 默认配置随程序分发：`config/default.yaml`
- 用户自定义配置存放位置：**程序同目录下** `config.yaml`（便于便携使用）
- 加载优先级：命令行参数 > 用户 config.yaml > default.yaml
- 首次运行不自动生成用户配置，用户需要时手动创建或复制默认配置

配置示例：
```yaml
# config.yaml
display:
  os: true
  motherboard: true
  cpu: true
  memory: true
  gpu: true
  storage: true
  network: true
  audio: true
  monitor: true

output:
  color: auto        # auto / always / never
  unicode: auto      # auto / always / never
```

## 3. 技术选型

| 用途 | 技术方案 | 说明 |
|------|----------|------|
| 硬件静态信息 | `wmi` (Python WMI 库) | Windows 核心数据源 |
| 实时资源占用 | `psutil` | CPU/内存/磁盘/网络实时数据 |
| GPU 详细信息 (NVIDIA) | `pynvml` | N 卡负载/显存/温度 |
| GPU 基本信息 (AMD/Intel) | WMI `Win32_VideoController` | AMD/Intel 显卡仅通过 WMI 获取基本信息 |
| 补充信息采集 | `subprocess` 调用 PowerShell/wmic | NVMe 详情、WiFi 信号等 |
| PCI ID 翻译 | 内置 pci.ids + 自写解析器 | 离线，约 1.5MB |
| CLI 框架 | `argparse`（标准库） | 轻量，CLI 为辅助工具 |
| GUI 框架 | PySide6 / PyQt6（第二阶段） | 待定 |
| EXE 打包 | PyInstaller | `--onefile --windowed` |
| 配置管理 | PyYAML | 读写 YAML 配置文件 |

## 4. 架构设计

### 4.1 分层架构

```
┌─────────────────────────────────────┐
│         入口层 (main.py)             │
│   无参数 → GUI ｜ 有参数 → CLI       │
├─────────────────────────────────────┤
│     CLI 层 / GUI 层（展示入口）       │
├─────────────────────────────────────┤
│     核心调度层 (core/)               │
│     CollectorManager 统一调度        │
├─────────────────────────────────────┤
│     采集层 (collectors/)             │
│     9 个独立模块，各自采集            │
├─────────────────────────────────────┤
│     格式化层 (formatters/)           │
│     terminal / json / html          │
├─────────────────────────────────────┤
│     工具层 (utils/)                  │
│     WMI封装 / pci.ids / PowerShell   │
└─────────────────────────────────────┘
```

### 4.2 采集模块设计

- 每个硬件类别对应一个独立的 Collector 模块
- 所有 Collector 继承统一基类 `BaseCollector`
- 通过注册机制自动发现，由 `CollectorManager` 统一调度
- 单个 Collector 失败不阻塞整体采集

### 4.3 数据结构

- 采集结果使用**普通 Python 字典 (dict)**
- 键名使用**中文**，直观可读，便于调试
- 嵌套结构用列表套字典表示（如多条内存、多块磁盘）
- 不使用 dataclass，降低复杂度

示例：
```python
{
    "名称": "Intel(R) Core(TM) i7-13700K",
    "厂商": "GenuineIntel",
    "核心数": 16,
    "线程数": 24,
    "基础频率_MHz": 3400,
    "指令集": ["SSE4.2", "AVX2", "SHA"],
}
```

## 6. CLI 命令设计

```bash
# 采集并显示全部硬件信息
hwinfo all

# 只看指定类别
hwinfo cpu gpu memory

# 隐藏某些类别
hwinfo all --hide audio,os

# JSON 格式输出
hwinfo all --json

# 简洁模式（每类只显示关键字段）
hwinfo all --brief

# 指定配置文件
hwinfo all --config my_config.yaml
```

## 7. 已知限制与约束

| 信息项 | 限制 | 处理方式 |
|--------|------|----------|
| CPU 制程 / TDP | WMI 无此字段 | 第一版不显示，后续可维护型号库 |
| CPU 大小核明细 | WMI 不直接区分 P/E Core | 尝试解析注册表或 CPUID |
| 内存 SPD 详细时序 (CL-tRCD-tRP) | 需内核驱动 | 第一版不采集 |
| GPU CUDA 核心数 | 仅 NVIDIA pynvml 可获取 | 有则显示，无则跳过 |
| NVMe 寿命/写入量 | 需管理员权限 | 无权限时提示 |
| 显示器 HDR/位深 | WMI 信息有限 | 尽力获取，不可靠则不显示 |
| WiFi SSID/信号 | 需调用 netsh 命令 | subprocess 实现 |
| 温度/风扇转速 | 需底层驱动 | 第一版不做，后续集成 LibreHardwareMonitor |

## 8. 开发计划（分阶段）

### 第一阶段：CLI + 数据采集（当前）

1. 搭建项目骨架（目录、基类、管理器）

5. 实现 CLI 命令解析（argparse）
6. 配置文件加载支持
7. 并行采集 + 超时机制
8. 真机全量验证（在本机运行，确认 9 类输出正确完整）

1. 选择 GUI 框架（PySide6 / PyQt6）
2. 主窗口 + Tab 页布局
3. 各硬件详情页
4. 实时监控图表（可选）

1. PyInstaller 打包为 EXE

## 10. 测试策略

| 测试类型 | 方式 | 说明 |
|----------|------|------|
| 采集正确性 | 真机手动验证 | 硬件信息因机器而异，无法用固定断言 |
| 模块单元测试 | Mock WMI 返回数据 | 验证解析逻辑、字段映射、异常处理 |
| 格式化输出 | 固定 dict 输入 → 断言输出字符串 | 不依赖真实硬件 |
| pci.ids 解析 | 已知 VEN/DEV → 断言品牌名 | 纯逻辑测试 |
| 配置加载 | 构造 YAML → 断言配置对象 | 纯逻辑测试 |
| 回归验证 | 每次改动后真机跑 `--json` 对比 | 确保不丢字段 |

## 11. 数据单位约定

| 物理量 | 键名后缀 | 示例 |
|--------|----------|------|
| 频率 | `_MHz` | `"基础频率_MHz": 3400` |
| 容量（内存/显存） | `_GB` | `"容量_GB": 16` |
| 容量（磁盘） | `_GB` | `"容量_GB": 1000.2` |
| 电压 | `_V` | `"电压_V": 1.1` |
| 温度 | `_C` | `"温度_C": 42` |
| 百分比 | `_百分比` | `"当前负载_百分比": 12` |
| 速率（网络） | `_Gbps` | `"速率_Gbps": 2.5` |
| 无单位/文本 | 无后缀 | `"名称": "..."` |

> 注：键名中的单位后缀是为了调试可读性。展示层负责格式化（如 3400 MHz → 3.4 GHz）。
