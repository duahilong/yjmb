# HWInfo — Windows 硬件检测工具 需求文档

> 版本：v1.2  
> 日期：2026-10-19  
> 状态：功能已实现并交付
>
> 说明：本版按**现有代码实现**校订，修正了早期需求与实现不符的描述

## 1. 项目概述

### 1.1 项目目标

开发一款 Windows 平台下的硬件检测工具，能够全面采集当前电脑的硬件信息并以清晰、直观的方式展示，类似于「鲁大师」「游戏加加」的硬件检测功能。

### 1.2 开发语言

Python

### 1.3 目标平台

Windows 10 / 11（64-bit）

### 1.4 产品形态

- **第一阶段**：CLI 命令行工具（开发验证 + 辅助使用）
- **第二阶段**：GUI 桌面应用（主产品形态）
- **最终交付**：打包为单文件 EXE，双击即可运行 GUI

### 1.5 运行环境与前置条件

| 项目 | 要求 |
|------|------|
| Python 版本 | ≥ 3.10（使用 `list[str]` 类型提示等） |
| 操作系统 | Windows 10 (1809+) / Windows 11，64-bit |
| WMI 服务 | 需正常运行（`winmgmt`），精简系统可能被禁用 |
| 终端编码 | 程序启动时强制设置 `stdout` 为 UTF-8，避免 GBK 乱码 |
| 管理员权限 | 非必须，仅影响磁盘健康类信息（v0.1 未采集，见 2.8） |

### 1.6 性能要求

| 指标 | 目标 |
|------|------|
| 全量采集耗时 | ≤ 5 秒（普通 SSD 主机），CLI 实测约 1.3~2s，GUI 顺序采集约 3.2s |
| 采集方式 | CLI 各模块**并行**执行（`concurrent.futures.ThreadPoolExecutor`，进程内共享复用）；GUI 改为**顺序**执行（原因见设计文档 §9.5） |
| 超时策略 | **软超时**：整体 15 秒（`TIMEOUT=10` + 5 秒余量）兜底；超时后放弃等待，未完成模块标记为「采集超时」 |
| WMI 连接 | **每线程独立**连接（`threading.local`），不可跨线程共享；首次创建需全局锁串行化 |

## 2. 功能需求

### 2.1 硬件信息采集（核心功能）

采集以下 **9 大类**硬件信息（下表为**实际已实现**的字段集）：

| # | 类别 | 采集内容 |
|---|------|----------|
| 1 | 操作系统 | 系统名称、版本号、系统架构、安装日期、上次启动、系统目录、用户名 |
| 2 | 主板 | 厂商、型号、版本、序列号、芯片组、BIOS 厂商/版本/日期、UEFI、TPM |
| 3 | 处理器 (CPU) | 名称、厂商、架构、插槽、核心数/线程数、基础频率、L2/L3 缓存、指令集、虚拟化支持、当前负载 |
| 4 | 内存 (RAM) | 总容量、已使用量、使用率、插槽总数/已用数、通道模式；每条内存的插槽位置/厂商/型号/容量/类型/频率/CL/位宽/电压/序列号 |
| 5 | 显卡 (GPU) | 独显/核显分类；名称、厂商、显存容量、驱动版本/日期、当前输出分辨率/刷新率、状态、负载、显存使用（后两项仅 N 卡） |
| 6 | 存储设备 | 每块磁盘的型号、类型(SSD/HDD，关键词推断)、接口(NVMe/SATA)、容量、固件、序列号；分区信息（盘符/标签/文件系统/已用/总容量） |
| 7 | 网络设备 | 有线/无线分类；名称、厂商、MAC 地址、速率、连接状态、IPv4/子网掩码/网关、驱动版本、SSID 及信号强度(无线) |
| 8 | 音频设备 | 所有声卡；名称、厂商、位置（板载/GPU附带/USB外接）、驱动版本、状态 |
| 9 | 显示器 | 型号、厂商、制造年份/周、分辨率、刷新率、当前状态 |

**未实现的字段（已知取舍）**

| 类别 | 字段 | 原因 |
|------|------|------|
| 存储设备 | 健康状态、介质类型 | 只能通过 PowerShell `Get-PhysicalDisk` 获取（WMI 无等价接口），进程启动固有开销约 1.5~2s，且需管理员权限 |
| 显卡 | DirectX 版本、总线接口、显存类型 | WMI `Win32_VideoController` 不提供可靠数据 |
| 显示器 | 连接方式 (DP/HDMI) | WMI 难以可靠获取，当前恒为空值 |
| CPU | 最大睿频、制程、TDP | WMI 无对应字段（`MaxClockSpeed` 已被用作"基础频率"） |
| 网络设备 | 总线位置 | WMI `Win32_NetworkAdapter` 未提供稳定字段 |

### 2.2 不采集的内容

- USB 外设（热插拔设备，不属于机器固有硬件）
- PCIe 全量设备列表（数据量过大，无实际展示价值）
- 电池信息（非目标场景）

### 2.3 厂商 ID 翻译

- 硬件设备的 VEN/DEV ID 需翻译为可读的品牌名称
- 方案：内置 `pci.ids` 离线数据库（来源：pci-ids.ucw.cz）
- 优先级（**以现实现为准**）：
  1. 使用 WMI 返回的设备友好名称（绝大多数设备有）
  2. WMI 名称缺失或为通用名（如空值 / "未知显卡" / 含 "video controller"）时，
     查询本地 pci.ids 翻译，返回「厂商名 + 设备名」的组合
  3. pci.ids 也查不到时，显示「未知显卡」（**尚未**显示原始 VEN/DEV ID，见优化计划 §3.4）
- **触发条件**：仅当名称或厂商缺失时才查询；pci.ids 数据库**懒加载**，
  名称厂商齐全的主流机器不承担 1.6MB 文件的解析开销

### 2.4 采集与展示分离

- **采集层**：尽可能全面地采集所有硬件信息，输出为结构化数据
- **展示层**：根据用户配置/参数，决定显示哪些类别、哪些字段
- 采集到的信息不要求全部展示，用户可自定义显示/隐藏

### 2.5 显示控制

- CLI 阶段：通过命令行参数控制（如 `hwinfo cpu gpu`、`--hide audio`）
- 配置文件：持久化用户的显示偏好（YAML 格式）
- GUI 阶段：设置页提供各类别开关，保存后重建导航并重新采集；
  **全部关闭时不采集任何类别**，不会退化为全量采集

### 2.6 输出格式

- 终端美化输出（框线、分组、状态符号）— 默认
- JSON 输出（`--json` 参数）— 调试及数据交换
- HTML 报告 — 后续扩展

### 2.7 容错处理

- 单个采集模块失败不影响其他模块（失败模块记入 `errors`，其余照常输出）
- 模块内局部字段获取失败时，字段置 `None` 或降级值，并在模块结果中附带 `_警告`
- 采集结束时汇总报告错误数 / 警告数（终端底部摘要，JSON 模式下为 `_错误` / `_警告` 键）

### 2.8 权限策略

- 程序**不强制要求管理员权限**
- **非管理员模式**（默认）：正常采集全部已实现字段
- v0.1 **不存在**需要管理员权限才能读取的字段——磁盘健康信息（SMART / 介质类型）
  已刻意不采集（见 2.1 表格注与设计文档 §4.7）
- 唯一的管理员相关行为：CLI 模式在**输出末尾**提示
  `提示：以管理员运行可获取更完整的磁盘健康信息`（JSON 模式不打印，避免污染数据）
- GUI 模式不做该提示

### 2.9 多设备场景

| 场景 | 处理方式 | 状态 |
|------|----------|------|
| 多块显卡（如双 N 卡） | 列表逐项输出，标题形如 `[独显] NVIDIA GeForce RTX 4070 Ti` | ✅ 已实现 |
| 多个显示器 | 列表逐项输出，标题形如 `DELL U2720Q` | ✅ 已实现 |
| 多块同型号硬盘 | 列表逐项输出，标题形如 `[SSD] Samsung SSD 980 PRO`，字段含序列号 | ✅ 已实现 |
| 多条同型号内存 | 按插槽位置区分，字段 `插槽` = `DIMM_A1` / `DIMM_B1` | ✅ 已实现 |
| 多个同类网络设备 | 列表逐项输出，标题形如 `[以太网] Realtek Gaming 2.5GbE` | ✅ 已实现 |

> **编号形式说明**：早期需求中的 `[独显 0]` / `[磁盘 0]` 编号形式**未实现**，
> 现实现统一使用 `[类型] 名称` 前缀。补齐编号见 `docs/后端优化计划.md` §3.5。

> **已知限制**：多张 NVIDIA 显卡时，pynvml 的负载/显存数据按下标顺序绑定，
> 与 WMI 列表顺序不保证一致，存在错配风险（优化计划 §2.3）。

### 2.10 终端兼容性

- 程序启动时检测终端是否支持 ANSI 转义序列（颜色/Unicode 框线）
- **支持时**（Windows Terminal / PowerShell 7+）：使用彩色输出 + Unicode 框线
- **不支持时**（老版 cmd.exe）：降级为纯 ASCII 分隔线 + 无颜色
- 检测方式：检查 `os.environ.get("WT_SESSION")` 或尝试启用 VT100 模式
- 提供 `--no-color` 参数强制关闭颜色
- Unicode 模式只能通过配置文件 `output.unicode` 控制（无命令行参数）

### 2.11 日志与调试

- 提供 `--debug` 参数，输出各 Collector 的执行耗时与采集摘要
- 调试信息输出到 **stderr**，不干扰正常的 stdout 数据输出
- 异常堆栈通过统一日志（`utils/logger.py`）输出到 stderr
- 不写日志文件（CLI 阶段），保持轻量
- GUI 模式为 windowed 无控制台，可通过环境变量 `HWINFO_LOG_LEVEL`
  （`DEBUG`/`INFO`/`WARNING`/`ERROR`）调整日志级别

### 2.12 版本与自身信息

- `hwinfo --version` 输出工具版本号（如 `HWInfo v0.1.0`）
- 终端美化输出的头部包含工具名称和版本号
- 版本号定义在 `pyproject.toml` 中，代码通过 `importlib.metadata` 读取

### 2.13 `--brief` 简洁模式字段定义

brief 模式分两级过滤：**顶层字段**（`BRIEF_FIELDS_MAP`）与
**列表项字段**（`ITEM_BRIEF_FIELDS_MAP`），定义在 `core/constants.py`，
CLI 与 GUI 总览页共用同一份定义。

| 类别 | 顶层字段 | 列表项字段（每条设备） |
|------|---------|---------------------|
| 操作系统 | 系统名称、版本号、系统架构 | — |
| 主板 | 厂商、型号、BIOS_版本 | — |
| CPU | 名称、核心数、线程数、基础频率_MHz | — |
| 内存 | 总容量_GB、已用插槽、通道模式 | 插槽、厂商、容量_GB、类型、频率_MHz、CL、电压_V |
| 显卡 | —（列表型） | 名称、显存_MB、驱动版本 |
| 存储 | —（列表型） | 型号、类型、容量_GB |
| 网络 | —（列表型） | 名称、驱动版本 |
| 音频 | —（列表型） | 名称、驱动版本 |
| 显示器 | —（列表型） | 型号、分辨率、刷新率_Hz |

> 「列表型」表示该类别的数据整体是一个设备列表（`{"显卡列表": [...]}`），
> 顶层字段留空，过滤完全由列表项字段控制。

### 2.14 配置文件

- 默认配置随程序分发：`config/default.yaml`
- 用户自定义配置存放位置：**程序同目录下** `config.yaml`（便于便携使用）
- 加载优先级：命令行参数 > 用户 config.yaml > default.yaml
- 首次运行不自动生成用户配置，用户需要时手动创建或复制默认配置

配置示例：
```yaml
# config.yaml
display:
  os: true
  motherboard: true
  cpu: true
  memory: true
  gpu: true
  storage: true
  network: true
  audio: true
  monitor: true

output:
  color: auto        # auto / always / never
  unicode: auto      # auto / always / never

collect:
  timeout: 10        # 单模块超时基数（秒），整体兜底为 timeout + 5
  parallel: true     # 是否并行采集

gui:                 # 仅界面使用，由 GUI 设置页写入，CLI 不读取
  theme: light           # light / dark
  density: comfortable   # compact / comfortable / large
  on_top: false          # 窗口置顶
  zoom: 1.0              # 界面缩放 0.7~1.6
```

- `display` 段同时控制 **CLI 采集范围**与 **GUI 导航项 / 采集范围**
  （GUI 设置页保存后重建导航并重新采集）
- `collect.timeout` / `collect.parallel` **只对 CLI 生效**：GUI 固定顺序采集，
  不走共享线程池与整体超时兜底（原因见设计文档 §9.5）
- `gui` 段由 GUI 自行读写，写回时保留其它段落，不覆盖手写配置

## 3. 技术选型

| 用途 | 技术方案 | 说明 |
|------|----------|------|
| 硬件静态信息 | `wmi` (Python WMI 库) + `pywin32` | Windows 核心数据源 |
| 实时资源占用 | `psutil` | CPU 负载、内存使用量 |
| GPU 详细信息 (NVIDIA) | `pynvml` | N 卡负载/显存使用量 |
| GPU 基本信息 (AMD/Intel) | WMI `Win32_VideoController` | AMD/Intel 显卡仅通过 WMI 获取基本信息 |
| 补充信息采集 | `subprocess` 调用 `netsh` / `powershell` | WiFi SSID 与信号强度 |
| 驱动版本 | Windows 注册表（`utils/registry.py`） | 绕开 `Win32_PnPSignedDriver`（3~5s → <10ms） |
| PCI ID 翻译 | 内置 pci.ids + 自写解析器 | 离线，约 1.6MB，懒加载 |
| CLI 框架 | `argparse`（标准库） | 轻量，CLI 为辅助工具 |
| GUI 框架 | PySide6 | 已落地（PySide6 ≥ 6.5） |
| EXE 打包 | PyInstaller | `--onefile --windowed`，禁用 UPX（见 8.3） |
| 配置管理 | PyYAML | 读写 YAML 配置文件 |
| 日志 | 标准库 `logging` | 统一输出到 stderr，不写文件 |

## 4. 架构设计

### 4.1 分层架构

```
┌─────────────────────────────────────┐
│         入口层 (main.py)             │
│   无参数 → GUI ｜ 有参数 → CLI       │
├─────────────────────────────────────┤
│     CLI 层 / GUI 层（展示入口）       │
├─────────────────────────────────────┤
│     核心调度层 (core/)               │
│     CollectorManager 统一调度        │
│     registry 注册 / constants 常量   │
├─────────────────────────────────────┤
│     采集层 (collectors/)             │
│     9 个独立模块，各自采集            │
├─────────────────────────────────────┤
│     格式化层 (formatters/)           │
│     terminal / json                 │
├─────────────────────────────────────┤
│     工具层 (utils/)                  │
│   WMI封装 / pci.ids / 注册表 /       │
│   PowerShell / 格式化 / 日志          │
├─────────────────────────────────────┤
│     配置层 (config/)                 │
│     default.yaml + 用户 config.yaml  │
└─────────────────────────────────────┘
```

### 4.2 采集模块设计

- 每个硬件类别对应一个独立的 Collector 模块
- 所有 Collector 继承统一基类 `BaseCollector`
- 通过注册机制自动发现，由 `CollectorManager` 统一调度
- 单个 Collector 失败不阻塞整体采集

### 4.3 数据结构

- 采集结果使用**普通 Python 字典 (dict)**
- 键名使用**中文**，直观可读，便于调试
- 嵌套结构用列表套字典表示（如多条内存、多块磁盘）
- 不使用 dataclass，降低复杂度

示例：
```python
{
    "名称": "Intel(R) Core(TM) i7-13700K",
    "厂商": "GenuineIntel",
    "核心数": 16,
    "线程数": 24,
    "基础频率_MHz": 3400,
    "指令集": ["SSE", "SSE2", "SSE3", "SSSE3", "SSE4.1", "SSE4.2", "AVX", "AVX2"],
}
```

## 6. CLI 命令设计

hwinfo all

hwinfo all --json

## 7. 已知限制与约束

| 信息项 | 限制 | 处理方式 |
|--------|------|----------|
| CPU 制程 / TDP | WMI 无此字段 | 不显示，后续可维护型号库 |
| CPU 大小核明细 | WMI 不直接区分 P/E Core | 不采集；后续可解析注册表或 CPUID |
| CPU 指令集精度 | 无 CPUID 探测，基于型号族启发式推断 | 缺 AVX-512 / FMA / SHA；优化计划 §2.1 |
| 内存 SPD 详细时序 (CL-tRCD-tRP) | 需内核驱动 | 不采集；仅从型号字符串解析 CL |
| 内存通道模式 | WMI 无通道拓扑字段 | 按已插条数推断；优化计划 §2.5 |
| GPU CUDA 核心数 | 仅 NVIDIA pynvml 可获取 | 不采集 |
| 多 N 卡的 pynvml 归属 | NVML 顺序与 WMI 顺序不保证一致 | 下标绑定，存在错配风险；优化计划 §2.3 |
| 磁盘 SMART / 介质类型 | 需 PowerShell（启动开销 ~2s）+ 管理员权限 | v0.1 不采集；优化计划 §3.3 |
| NVMe 寿命/写入量 | 需管理员权限 | v0.1 不采集 |
| 显示器 HDR/位深/连接方式 | WMI 信息有限 | 不显示（连接方式恒为空值） |
| WiFi SSID/信号 | 需调用 netsh 命令 | subprocess 实现（按本地 ANSI 代码页解码） |
| 温度/风扇转速 | 需底层驱动 | 不做，后续集成 LibreHardwareMonitor |
| 多设备编号 | 需求中的 `[独显 0]` 编号未实现 | 现为 `[类型] 名称`；优化计划 §3.5 |

## 11. 数据单位约定

| 物理量 | 键名后缀 | 示例 |
|--------|----------|------|
| 频率 | `_MHz` | `"基础频率_MHz": 3400` |
| 容量（内存/显存） | `_GB` / `_MB` | `"容量_GB": 16` |
| 容量（磁盘） | `_GB` | `"容量_GB": 931.5` |
| 位宽 | `_bit` | `"位宽_bit": 64` |
| 电压 | `_V` | `"电压_V": 1.35` |
| 温度 | `_C` | `"温度_C": 42`（当前无采集点） |
| 百分比 | `_百分比` | `"当前负载_百分比": 12` |
| 速率（网络） | `_Gbps` | `"速率_Gbps": 2.5` |
| 无单位/文本 | 无后缀 | `"名称": "..."` |

> 注 1：键名中的单位后缀是为了调试可读性。展示层负责格式化（如 3400 MHz → 3.4 GHz）。
>
> 注 2：容量换算统一按 `1024` 进制（GiB / MiB），因此 1TB 磁盘显示为 `931.5 GB`；
> 网络速率按 `1000` 进制（Gbps）。
