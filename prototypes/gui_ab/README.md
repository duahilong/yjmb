# HWInfo GUI 原型 A / B

这是 GUI 重写前的静态原型，只用 mock 数据验证视觉方向和信息架构，不接真实采集、不改动现有 `gui/`。

## 运行

```bash
# 直接打开两版窗口（需要有桌面环境）
python prototypes/gui_ab/prototype_a.py
python prototypes/gui_ab/prototype_b.py

# 渲染成 PNG（写入 out/，用于并排评审）
python prototypes/gui_ab/render.py
```

> 渲染脚本使用 `windows` 平台插件；`offscreen` 在 Windows 上拿不到系统字体，中文会变成方框。

## 方案 A：Bench Sheet / 工程铭牌

- 定位：像仪器铭牌 + 工程规格表，浅色、密集、可扫读
- 结构：深色左导轨 + 机器身份条 + 系统带 + 规格表 + 采集摘要侧栏
- 特征：Bahnschrift 大字号型号、等宽数字、细线分隔、橙色信号色只用于选中与关键动作

## 方案 B：Night Bench / 深色诊断台

- 定位：深色诊断台，突出实时监控与系统拓扑
- 结构：顶部品牌栏 + 横向标签 + 自绘系统拓扑 + 实时指标（sparkline）+ 设备清单
- 特征：自绘节点/连线/网格、琥珀色主 accent、绿/蓝状态色、LIVE 实时语义

## 对比要点

| 维度 | A Bench Sheet | B Night Bench |
|---|---|---|
| 气质 | 工程数据表、可信、克制 | 诊断台、沉浸、偏玩家 |
| 信息密度 | 高，适合一次看全 | 中，拓扑与曲线占空间 |
| 实时监控 | 不适合 | 天然适合 |
| 长时间阅读 | 好 | 一般 |
| 实现成本 | 较低（表格 + QSS） | 较高（自绘拓扑、sparkline） |
| 截图传播 | 干净、像报告 | 抢眼、像监控台 |
| 与「单文件 EXE 体积优先」 | 契合，系统字体即可 | 契合，系统字体即可 |

## 当前优先级（用户已确认）

- 首版优先：**单文件 EXE 体积优先** + **实时监控**
- 这两点对 A 不利：A 没有实时监控；B 需要自绘和定时刷新，但不需要额外依赖或大字体包，EXE 体积仍然可控。
